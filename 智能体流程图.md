### MatchScorer 匹配算法

> 返回后进入主流程 `algorithmic_match` 节点

```
  MatchScorer.compute_scores(profile, job_reqs)

  对每个维度 i (共7个):
    gap = expected - user_score

    gap <= 0 → dim_score = 100 - |gap| * 0.3    (超出扣分少)
    gap >  0 → dim_score = max(0, 100 - gap*1.2) (差距扣分重)

  total = Σ(dim_score × weight[i])
  权重: [0.18, 0.13, 0.15, 0.16, 0.10, 0.10, 0.18]

  按 total_score 降序排序 → match_results
```

## 五、智能体四：周任务生成器 (weekly_task_generator)

> `agent_id = "weekly_task_generator"` | `cacheable = False` | `timeout = 60s`
> 直接 LLM 调用: 1 次 | 无子模块
> 功能: 一次性生成 7 天实训任务列表（周任务），不承担交互与指导职责
> 交互与指导由智能体五（task_guide）负责

### 节点详解

#### 1. load_profile_and_job（无 LLM）
- 加载用户画像（`user_profiles` 表）: 雷达图 7 维数据 + 维度详情
- 加载目标岗位（`user_selected_job` 表）: 岗位名称、能力要求
- 计算能力差距（用户画像 vs 岗位要求）: `skill_gaps`
- 输入: 用户 ID
- 输出: `{ user_profile, target_job, skill_gaps }`

#### 2. retrieve_resources（无 LLM）
- 使用 ChromaDB 向量检索与目标岗位、技能差距相关的学习资源
- 检索 Top-K 资源（文章、课程、项目案例等）
- 输入: `{ target_job, skill_gaps }`
- 输出: `{ resources: [{title, url, type, description}] }`

#### 3. generate_weekly_tasks（★ LLM, temp=0.5）
- 输入: `{ target_job, skill_gaps, resources }`
- 输出: 7 天 × 1~3 个任务，每个任务包含标题、描述、类型
- 任务类型: `reading`（阅读/学习）, `practice`（练习/刷题）, `project`（项目/实战）, `review`（复习/总结）
- 一次性生成完整周任务列表，不涉及对话或交互

#### 4. save_daily_tasks（无 LLM）
- 将生成的周任务写入 `daily_tasks` 表
- 每条记录: `{ user_id, task_date, tasks (JSON), completed=false }`
- 供智能体五（task_guide）读取并引导用户执行

### 入参出参

| 项目 | 说明 |
|------|------|
| 输入 | `user_id`, `target_job_id`（从 `user_selected_job` 读取） |
| 输出 | 7 天任务列表，写入 `daily_tasks` 表 |
| 触发时机 | 用户锁定目标岗位后，触发"生成周任务" |
| 缓存策略 | 不缓存（每次重新生成） |
| 与智能体五分工 | 智能体四只负责"一次性生成"，智能体五负责"交互与指导" |

### 节点详解

#### 1. load_task（无 LLM）
- 从 `daily_tasks` 表加载用户当前实训任务（任务名 + 要求描述）
- 加载用户画像（`user_profiles` 表），供后续引导与评估参考
- 输入: `task_id` / 用户ID
- 输出: `{ task: {text, desc, type}, user_profile }`

#### 2. route_intent（条件路由）
- 读取前端请求类型，分流到三个对话分支
- 判断依据: 请求类型标识（初始引导 / 过程指导 / 提交评估）
- 对应前端: 点击任务卡片自动触发 → 初始引导；聊天输入 → 过程指导；提交答案按钮 → 提交评估

#### 3. guide — 初始引导（★ LLM, temp=0.7）
- 触发: 用户点击任务卡片，前端自动发送引导请求
- 输入: `[当前实训任务] 任务名 + 要求` + 用户画像
- 行为: 以任务导师身份说明完成该任务需掌握的关键点、推荐的学习方法，并询问用户准备如何开始
- 输出: ≤120 字纯文本引导语

#### 4. coach — 过程指导（★ LLM, temp=0.7）
- 触发: 用户在对话中发送消息
- 输入: `[当前实训任务] 任务名 + 要求` + 用户消息 + 最近 10 条对话历史
- 行为:
  - 围绕任务逐步拆解，一次只提出 1 个子问题或考查点
  - 收到用户思路后指出盲点与可改进处，再给提示或同类练习
  - 不直接给出答案或完整实现
  - 自然评估用户水平（基础/进阶/熟练）
- 输出: ≤120 字纯文本回复，禁止 markdown

#### 5. evaluate — 提交评估（★ LLM, temp=0.7）
- 触发: 用户点击"提交答案"，请求带 `submission=true`
- 输入: `[当前实训任务] 任务名 + 要求 + 这是用户的最终提交` + 用户答案
- 行为: 评估用户对该任务的掌握程度，指出不足，给出下一步改进建议
- 输出: 评估结论 + 改进建议

#### 6. update_profile（子模块 profile_analyzer，2 次 LLM）
- 每轮对话后自动执行（无论哪个分支）
- 输入: 完整对话历史 + 上一轮画像（radar_data / dimension_details）
- 流程: LLM 提取信息（temp=0.3）→ LLM 评分（temp=0）→ 证书算法评分 → 基准分兜底 → 维度关联推断 → EMA 平滑
- 输出: 更新后的 7 维画像，保存到 `user_profiles` 表，供 job_matcher 等复用

### 对话流程三阶段

| 阶段 | 触发 | 请求特征 | 导师行为 |
|------|------|----------|----------|
| 初始引导 | 点击任务卡片 | 自动调用，无用户消息内容 | 说明关键点 + 学习方法 + 询问准备 |
| 过程指导 | 聊天输入 | 用户消息 + task_context | 逐步拆解、出题、指出盲点 |
| 提交评估 | 提交答案按钮 | submission=true + 用户答案 | 评估掌握程度 + 改进建议 |
